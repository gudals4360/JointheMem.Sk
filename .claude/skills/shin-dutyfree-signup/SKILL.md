# 신세계면세점 회원가입 UX 프로토타입

실제 가입·인증 서버가 없는 **UX 검증용 프론트엔드 프로토타입**이다. 실제 인증이나 탈퇴 이력 조회를 한 것처럼 표현하지 않는다. 원격: `tmddn718-dev/Shin_DutyFree`.

## 구성

- 결과물은 **루트의 `index.html` 하나**(HTML+CSS+JS 인라인). 빌드 도구·외부 라이브러리 없음. 외부 리소스는 Pretendard 웹폰트 CDN과 카카오 우편번호 스크립트뿐.
- 디자인 시스템은 `gs-shop.md`. 색은 이 토큰만 쓴다(파랑 `#0F78FF`/`#0A61EB`, 회색면 `#F5F6FA`, 글자 `#191923`/`#72728A`, 성공 `#12891D`, 오류 `#C00002`). GS SHOP의 클래스명·로고·워드마크는 노출하지 않는다.

## 화면 흐름 (한 페이지 안에서 전환)

`entry(1/4 가입 방식) → verification(2/4 본인 인증) → info(3/4 정보입력) → consent(4/4 약관 동의) → done(가입 완료)`

| 화면 | 래퍼 id | 스타일 범위 | 비고 |
|---|---|---|---|
| 가입 방식 선택 | `#v-entry` | `.ev` | 혜택 일러스트 캐러셀(스와이프, 자동 전환 없음), 버튼·캡션 간격 12/24px |
| 본인 인증 | `#v-verification` | `.ev` | 인증 수단 3개 중 선택, 선택하면 버튼 문구 변경(모의 인증) |
| 정보입력 | `#v-info` | `si-` 접두사 클래스 | 아이디 중복확인, 비밀번호 규칙 체크리스트, 이메일 확인(6개 상태), 자택주소(선택, 카카오 우편번호) |
| 약관 동의 | `#v-consent` | `.cs` | 전체 동의, 필수 3개, 선택 2개(통합 서비스 9개, 마케팅 수신)는 아코디언 |
| 가입 완료 | `#v-done` | `.cs-old` | 동의 현황, 마스킹된 회원정보 |

- 전환은 `go(name)`(history.pushState) / `show(name)` / `popstate`. 뒤로가기는 `[data-back]` 또는 `history.back()`. 다음으로 가는 버튼은 `[data-go="…"]`.
- 화면 숨김은 `hidden` 속성. 정보입력 CSS의 `[hidden]{display:none!important}`에 의존하므로 래퍼에 `display`를 직접 주지 않는다.
- 정보입력 완료 시 `shin:info-complete` 이벤트(detail에 입력값, 비밀번호 포함)가 발생하고, 글루 코드가 완료 화면에 이름·휴대폰·이메일을 마스킹해 넣은 뒤 약관 동의로 이동한다.

## CSS 스코프 규칙 (충돌 방지)

세 팀원이 만든 화면을 합친 파일이라 클래스 이름이 겹친다. 반드시 **스코프 안에서만** 고친다.

- `.ev …` 가입 방식·본인 인증. 안쪽은 CSS nesting으로 작성돼 있다.
- `#v-info .si-…` 정보입력. 새 규칙은 파일 끝에 두고 `#v-info`로 시작해 특이도를 높인다.
- `.cs …` 약관 동의(새 스타일). `.cs-old …` 가입 완료(기존 스타일). 둘을 합치지 않는다. 가입 완료를 새 스타일로 바꾸려면 HTML과 CSS를 함께 바꾼다.
- 같은 클래스(`.caption`, `.btn`, `.card` 등)가 여러 화면에 있다. 한 화면만 바꿀 때는 `#v-화면id …` 규칙을 추가한다. 스코프 중첩 때문에 더 높은 특이도 규칙이 낮은 규칙을 덮는 경우가 많다(예: 본인 인증용 `.content .caption`이 가입 방식 화면에 번졌던 사례).

## 핵심 로직 위치

- 이메일 확인: `config.checkEmail`(모의 응답, 서버 연동 지점), `emailStatus`/`emailState`, `renderEmail()`, `syncEmail(valueChanged)`, `emailOk()`. 모의 규칙은 아이디가 `rejoin`으로 시작하면 재가입 가능, `blocked`로 시작하면 가입 제한, 그 외 신규. 확인 완료 전에는 `isComplete()`가 false라 "다음"이 잠긴다.
- 아이디 중복확인: `config.checkIdAvailable`(모의, `admin`/`shinsegae`/`test1234`/`gudals4360`이 사용 중).
- 본인 인증 값: 데모 값(김신세/010-1234-5678)이 정보입력에 들어간다.
- 캐러셀: `#crTrack`, `#crDots`, `go(i)`/`mark(i)`. 터치는 scroll-snap, 마우스는 포인터 드래그(40px 이상 끌면 다음/이전).

## 작업 방법

1. 서버: `python3 -m http.server <포트>`를 repo 루트에서 실행 후 `http://localhost:<포트>/index.html`. 끝나면 서버를 끈다. (`file://`로 열어도 되지만 미리보기 패널은 정적 스냅샷이라 CSS가 빠진다.)
2. 모바일 검증은 375×812 뷰포트. 끝나면 데스크톱으로 되돌린다.
3. 전환은 `go('info')`처럼 콘솔에서 바로 호출해 화면을 건너뛸 수 있다. 입력 테스트는 `input`/`change` 이벤트를 dispatch해야 상태가 갱신된다.
4. 간격은 `getBoundingClientRect()`로 실측해 말한 값과 맞는지 확인한다.
5. 미리보기 창에서는 `scroll-behavior: smooth`가 움직이지 않고 `scroll` 이벤트가 오지 않을 수 있다. 캐러셀 상태는 `go()`가 직접 `mark()`하도록 되어 있으니 이 점을 깨지 않는다.
6. 스크린샷이 한 박자 늦게 찍히는 경우가 있다. 상태는 JS로 읽어 교차 확인한다.

## 브랜치·커밋 규칙

- `main`: 팀 통합본. `redesign/ui-refresh`: 전체 UI 개편 실험 브랜치(두 가지 톤 제목, 채움형 입력창, 가입 완료 개편 등이 더 들어 있다). 토스 스타일 시도는 되돌렸다.
- 사용자가 "main에 적용"이라고 하면 **해당 화면 부분만** 옮긴다. 다른 화면에 영향이 가면 스코프를 나눠서 옮긴다.
- 브랜치를 오갈 때는 작업 중인 변경을 `git stash`로 보관했다가 되돌린다. 푸시 전에 `git fetch`로 원격 새 커밋을 확인하고 필요하면 rebase한다(다른 세션이 `main`에 직접 푸시하는 경우가 있었다).
- 커밋·푸시는 사용자가 요청할 때만 한다. 커밋 메시지는 한국어, 끝에 `Co-Authored-By` 줄을 붙인다.

## 접근성·정책 원칙

- 색만으로 상태를 구분하지 않는다(아이콘+문구 병행). 포커스 스타일 유지, 버튼은 실제 `<button>`.
- 재가입 가능 이메일은 오류가 아니라 성공(초록 체크)으로 안내한다.
- 프론트 코드에 실제 이메일·탈퇴 이력을 넣지 않는다. 이메일 소유 확인 전 탈퇴 이력 노출은 정책 검토가 필요하다는 주석을 유지한다.
- 실제 효과(선택 시간 단축 등)는 사용성 테스트 전에 성과로 단정하지 않는다.
